# NPCasso Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A cosy Luanti village whose NPCs remember, judge and gossip about the player, with every NPC reaction, intent read and conversation going through Mubit as three stable recurring tasks.

**Architecture:** A Luanti mod (`npcasso`) detects actions and witnesses, and shows dialogue and notices. It talks over HTTP JSON to a FastAPI backend that owns all state (SQLite), all rules, memory retrieval and the validator. The backend calls the LLM through the stock `openai` client, which points at a mock, a local server or Mubit.

**Tech Stack:** Luanti (latest stable) + Asuna game + cottages mod, Lua; Python 3.13, FastAPI, uvicorn, `openai`, `python-dotenv`, stdlib `sqlite3`, pytest, httpx.

**Spec:** `docs/superpowers/specs/2026-10-23-npcasso-design.md`

## Global Constraints

- Hackathon: all code written during the event; demo LLM traffic goes through Mubit (`LLM_PROVIDER=mubit`). `local` is for development only.
- No credentials in Lua or git. `.env` (gitignored) holds `LLM_PROVIDER=mock|local|mubit`, `LLM_MODEL`, `MUBIT_API_KEY` (starts `mbt_`), `MUBIT_BASE_URL=https://api.mubit.ai/openai/v1`, `LOCAL_BASE_URL=http://localhost:11434/v1`, `NPCASSO_DB=npcasso.db`. `.env.example` has placeholders only.
- System prompts are fixed constants per task and never contain NPC names or per-call data. All variable data goes in the user message as JSON (`json.dumps(..., sort_keys=True)`).
- The output JSON schemas of the three tasks are frozen once Task 12 makes the first Mubit call. The model never changes after that.
- The LLM proposes, the game decides: only `rules.py` and `game.py` change trust, promises, quests or events.
- Relationships are hidden from players: no trust, hearts or mood in nametags or HUD. The only exception is `/npcasso debug`.
- Player identity is `f"{world}:{player}"`, so two worlds never share state.
- Windows + PowerShell. Run tests with `.venv\Scripts\python -m pytest`.

## Review Focus

1. **Backend down or slow while the player talks:** Lua shows "<Name> seems distracted." and never errors; the HTTP timeout is 15 s; the formspec stays usable. Pinned in Task 9, manual check 5.
2. **LLM returns non-JSON, empty output or a timeout:** `/talk` still returns 200 with the neutral line; `/event` still stores the memory with template text. Pinned in Task 5 `test_react_llm_error_still_records` and Task 6 `test_talk_malformed_llm_neutral`.
3. **Two demo worlds on one backend:** the same player name in two worlds has independent trust and memories. Pinned in Task 5 `test_worlds_isolated`.
4. **Message is empty, whitespace or huge:** rejected with 422 before any LLM call. Pinned in Task 6 `test_talk_rejects_bad_message`.
5. **NPC added to `npcs.json` after the DB exists:** it appears on the next backend start without a migration. Pinned in Task 1 `test_new_npc_seeded_on_reconnect`.

**Interfaces:**
- Produces:
  - `db.load_config() -> dict`: parsed `backend/npcs.json`.
  - `db.connect(path: str) -> sqlite3.Connection`: `row_factory=sqlite3.Row`; creates the schema if missing; upserts every NPC from config.
  - `db.add_event(conn, ev: dict) -> int`: keys `player, type, actor, target, details (dict), witnesses (list), game_time, source ('game'|'llm_classified'), verified (bool), confidence (float|None)`.
  - `db.get_trust(conn, npc_id, player) -> int`: default `config["start_trust"]`.
  - `db.add_trust(conn, npc_id, player, delta) -> int`: clamps to -100..100 and returns the new value.
  - `db.add_memory(conn, npc_id, player, event_id, type, text, how, reliability, severity) -> int`
  - `db.top_memories(conn, npc_id, player, limit=5) -> list[dict]`: dicts with `event_id, type, text, how, reliability`. Order: severity desc, then ts desc.
  - `db.add_interaction(conn, row: dict) -> int` and `db.list_interactions(conn, npc_id=None, limit=50) -> list[dict]`
  - `db.add_promise(conn, kind, npc_id, player, item, count, deadline, reward=None) -> int`, with `kind` `'promise'|'quest'`.
  - `db.open_promises(conn, npc_id=None, player=None, kind=None) -> list[dict]`
  - `db.update_promise(conn, id, **fields)`
  - `db.get_flag(conn, npc_id, player, key)` / `db.set_flag(...)`: JSON `flags` column on `relationships` (used for `last_apology`).

Tables (from the spec, with these extra columns):
- `memories.player`, `memories.severity`, `memories.gossiped INTEGER DEFAULT 0`
- `promises.kind`, `promises.reward`

### Task 2: Deterministic rules

**Files:**
- Create: `backend/rules.py`, `tests/test_rules.py`

**Interfaces:**
- Consumes: `db.load_config()`
- Produces:
  - `trust_delta(event_type: str, how: str = "witnessed", gift_pref: str | None = None) -> int`: for `gift`, uses `deltas["gift_"+gift_pref]`. `how` starting with `told` gives `int(delta / 2)`. Unknown type gives 0.
  - `band(trust: int) -> str`: `<= -50` is `"hostile"`, `< -10` is `"wary"`, `< 30` is `"neutral"`, otherwise `"friendly"`.
  - `gift_pref(npc_cfg: dict, item: str) -> str`: `"loved"|"liked"|"disliked"|"neutral"`, where `item` is a short name.
  - `short_item(itemstring: str) -> str | None`: reverse of `config["items"]`.
  - `trade_terms(npc_cfg: dict, trust: int, work_block_present: bool = True) -> dict`: returns `{"ok": True, "give": {"item","count"}, "cost": {"item","count"}}` or `{"ok": False, "reason": "hostile"|"no_work_block"}`. Cost count is `base_price` × {friendly 1, neutral 2, wary 3}. Hostile refuses. `no_work_block` applies only if the NPC has a `work_block` and it's missing.
  - `apology_allowed(last_game_time: float | None, now: float) -> bool`: true if None or `now - last >= 1.0`.

### Task 3: LLM clients and the three task prompts

**Files:**
- Create: `backend/llm.py`, `tests/test_llm.py`

**Interfaces:**
- Produces:
  - `@dataclass LLMResult(data: dict | None, raw: str, request_id: str | None, latency_ms: int, tokens: int | None, error: str | None)`
  - `SYSTEM_PROMPTS: dict[str, str]` with keys `"npc_react"`, `"intent_classify"`, `"npc_dialogue"`. Each prompt explains the user JSON fields and ends with the exact output schema:
    - `npc_react`: `{"shout": str, "memory": str, "claims": [{"event_id": int|null, "type": str, "how": "witnessed"|"told"}]}`
    - `intent_classify`: `{"intent": "threat"|"apology"|"insult"|"promise"|"question"|"trade"|"correction"|"other", "confidence": number, "promise": {"item": str, "count": int, "deadline_days": number}|null, "claim": {"type": str, "item": str|null}|null}`. `claim` is the event the player says did NOT happen.
    - `npc_dialogue`: `{"reply": str, "claims": [...same as react...], "quest_offer": {"item": str, "count": int, "reward": str}|null}`
    - Dialogue and react prompts must say: speak only from `memories` and `facts`; list every past event mentioned in `claims` with its `event_id`; treat `how: told_by:*` memories as rumour; never reveal numbers or trust; use `validator_feedback` when present.
  - Protocol: `.complete(task: str, user: dict, thread_id: str) -> LLMResult`
  - `MockLLM()`: deterministic, no network.
    - classify: `sorry|apolog` gives apology 0.9; `i'll bring|i will bring|promise` gives promise 0.9, parsing `(\d+)\s+(\w+)` for count and item, with `deadline_days` 1; `never gave|didn't give|did not give` gives correction 0.9 with `claim {"type":"gift","item":<word after give/gave or null>}`; `kill|hurt|burn` gives threat 0.8; otherwise question 0.5.
    - dialogue: reply mentions the first memory's `text`; claims that memory's `event_id`/`type` with `how` = `"told"` if it starts with `told` else `"witnessed"`; with no memories, a greeting and `claims: []`.
    - react: `shout` = `"Hey! I saw that!"`, `memory` = `f"I saw them: {event type}"`, and claims the event.
  - `OpenAICompatLLM(base_url: str, api_key: str, model: str, send_metadata: bool, timeout: float = 20, http_client=None)`: uses `client.chat.completions.with_raw_response.create(model=..., messages=[system, user], response_format={"type": "json_object"}, **({"metadata": {"thread_id": thread_id}} if send_metadata else {}))`. Reads `x-middleware-request-id` from `raw.headers` and parses `raw.parse()`. On any exception or invalid JSON, returns `data=None, error=str(e)`.
  - `make_llm(provider: str) -> MockLLM | OpenAICompatLLM`: `mubit` uses `MUBIT_BASE_URL`, `MUBIT_API_KEY` and `send_metadata=True`; `local` uses `LOCAL_BASE_URL`, key `"local"` and `send_metadata=False`; `mock` returns `MockLLM()`. Unknown provider raises `ValueError`.

### Task 4: Validator

**Files:**
- Create: `backend/validator.py`, `tests/test_validator.py`

**Interfaces:**
- Consumes: the `context` dict built by `game.py`, with `memories` list items `{event_id, type, how, ...}`, `relationship.band`, and `items` (short names).
- Produces: `validate(task: str, output: dict | None, context: dict) -> dict` returning `{"ok": bool, "errors": [str], "flags": [str], "drop_quest": bool}`.
  - `output is None`, or the text key is missing or empty (`reply` for dialogue, `shout` for react), or `claims` isn't a list: error `"malformed"`.
  - A claim whose `event_id` isn't in context memories: `"invented_event:<id>"`. A null `event_id`: `"invented_event:null"`.
  - Matching id with a different `type`: `"type_mismatch:<id>"`.
  - Claim `how == "witnessed"` while the memory's `how` starts with `told`: `"rumour_as_fact:<id>"`.
  - Reply text contains an event word (`stole, steal, theft, thief, gift, gave, broke, smashed, hit, promised`) and `claims` is empty: flag `"unclaimed_mention:<word>"`.
  - Band `hostile` or `wary` and reply contains a warm word (`friend, dear, lovely, glad, welcome`): flag `"tone_mismatch"`.
  - `quest_offer` with an item not in context `items`: `drop_quest=True` (not an error).
  - `ok` = no errors.

### Task 6: Talk: classify, apply effects, dialogue, validate, retry

**Files:**
- Modify: `backend/game.py`, `backend/app.py`, `tests/test_game.py`, `tests/test_api.py`

**Interfaces:**
- Produces:
  - `NEUTRAL_LINE = "Hm. Let me think on that."`
  - `game.talk(conn, llm, world, player, npc_id, message, thread_id, game_time) -> dict` returning `{"reply": str, "notices": [str], "quest_offer": dict | None}`. Order:
    1. `intent_classify` with `{"npc": {name, role}, "player_message": message}`; store the interaction.
    2. If `confidence >= 0.6`, apply the intent:
       - **threat / insult:** `add_event` (source `llm_classified`, verified False, with confidence) and a trust delta.
       - **apology:** if `apology_allowed(flag last_apology)`, add +10, set the flag and add the notice `f"{Name} noticed your apology."`. Otherwise no change.
       - **promise:** if the item is known, `add_promise(kind="promise", deadline=game_time + deadline_days)` and set `extra_facts["new_promise"]`.
       - **correction:** search events for `type == claim.type`, `target == npc_id`, `player` and (if given) the item. If none exists, it's confirmed: +5, set `outcome="corrected"` on the latest `npc_dialogue` interaction for this npc/player, and `extra_facts["correction"] = {"confirmed": True, "claim": claim}`. If one exists, `{"confirmed": False, ...}` (the player denied a true event). *(Deviation from spec §7 "Player corrections": memories come only from verified events, so they can't be false and there's nothing to retract. The wrong thing is the previous reply, so the correction is logged on that interaction instead. No `retracted` column.)*
    3. Run `npc_dialogue` with `build_context(..., extra_facts)` and validate.
    4. If not ok, retry once with `context["validator_feedback"] = errors`. If still not ok, return `NEUTRAL_LINE`. Store both interactions with `retried`, `validator_result`, `request_id`, `latency_ms`, `tokens`, `prev_id`.
    5. A valid `quest_offer` (not `drop_quest`) gets `add_promise(kind="quest", deadline=game_time + 2, reward=offer["reward"])`.
  - `POST /talk` with `TalkIn{world, player, npc_id, message: str (1..500 after strip), thread_id, game_time}` returns the talk result.

### Task 7: Trade, promises, quests, gossip and ticks

**Files:**
- Modify: `backend/game.py`, `backend/app.py`, `tests/test_game.py`

**Interfaces:**
- Produces:
  - `game.trade_quote(conn, world, player, npc_id, work_block_present: bool) -> dict`: `rules.trade_terms` with item short names mapped to itemstrings. The actual trade is then reported by Lua as `/event` type `trade`.
  - Gift progress inside `record_event`: a `gift` whose short item matches an open promise or quest for the target npc and player decrements its count.
    - Promise at 0: status `kept`, an internal `promise_kept` event, +15, notice `f"{Name} noticed you kept your word."`

Every other NPC without a memory of that event gets `add_memory(how=f"told_by:{source}", reliability=0.5, severity=severity // 2)` and `trust_delta(type, "told")`. The source memory is marked `gossiped = 1`. A `told` event is recorded.
