# NPCasso v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A town with progression: realistic gossip, three new villagers, quests with a journal and board, XP/levels, monsters outside the village, a crafting table, auto-talk, a bottom-left feed, and a festival vote ending decided by hidden trust.

**Architecture:** Same split as v1. Python owns all state and rules (`backend/game.py`, `rules.py`, `db.py`, plus a new `backend/progress.py` for XP, quests and festival). The Lua mod renders and reports events. The three LLM tasks and their output schemas are unchanged.

**Tech Stack:** unchanged (FastAPI, sqlite3, openai client, pytest; Luanti 5.17 + Asuna + cottages), plus ContentDB `mobs` + `mobs_monster`.

**Spec:** `docs/superpowers/specs/2026-10-24-npcasso-v2-design.md` (on top of `2026-10-23-npcasso-design.md`)

## Global Constraints

- Three LLM tasks and their output JSON schemas stay unchanged. New per-call data goes in the user JSON only.
- XP, levels, quest progress and completion, rewards, votes and endings are deterministic backend code. Never LLM.
- Player key is `f"{world}:{player}"`, where world is the per-save id from Lua.
- Quests never expire. Spoken promises keep deadlines.
- Levels: Lv n+1 at `50*n*(n+1)/2` total XP (Lv2 = 50, Lv3 = 150, Lv4 = 300).
- Run tests with `.venv/Scripts/python -m pytest -q`. Check Lua with the headless server load (`luanti.exe --server` on a temp world, grep for `ERROR`).

## Review Focus

1. **Handing in more items than a quest needs:** only the needed count is consumed. Pinned in Task 4 `test_handin_takes_only_needed`.
2. **Two quests wanting the same item:** a hand-in fills the oldest first and never double-counts. Pinned in Task 4 `test_handin_two_quests_same_item`.
3. **Festival requested twice, or before it's eligible:** 409/422 and no state change. Pinned in Task 5 `test_festival_once_and_gated`.
4. **Gossip with only one villager knowing anything, or none:** tick is a no-op and never errors. Pinned in Task 1 `test_gossip_noop`.
5. **Monster dies with no player killer** (lava, fall): no slay event. Pinned in Task 9, manual check.

### Task 1: Face-to-face gossip (backend)

**Supersedes the tick-based design below.** `tick` no longer gossips. New
`game.gossip(conn, world, player, teller, listener, game_time, roll: float) -> {"line": str|None, "reply": str|None}`:
the teller's most severe memory about this player with severity >= 10, reliability >= 0.25, known by the teller for
>= GOSSIP_DELAY, whose event the listener doesn't know. Returns no line if there's none, or if
`roll >= chattiness(teller)` and it isn't (a crime and the listener is wren). Otherwise the listener gains a memory:
`told_by:<teller>`, reliability halved, severity // 2, learned_at = game_time, trust delta
`round(trust_delta(type) * new_reliability)`, plus a `told` event. The line is `"Psst... " + describe(type, None,
target, item)` and the reply is "Really?!". Route: `POST /gossip {world, player, teller, listener, game_time}`, with
the backend rolling `random.random()`.
Tests: `test_gossip_needs_meeting` (tick spreads nothing), `test_gossip_delay`, `test_gossip_reliability_halves`,
`test_low_chattiness_still_tells_wren_crimes`, `test_gossip_noop`.

Old sketch (superseded):

**Files:** Modify `backend/game.py` (`tick`), `tests/test_game.py`

**Interfaces:**
- `memories` gains `learned_at REAL`: game_time when this NPC learned it. Set by `add_memory(..., learned_at=game_time)`, default `None`, meaning "long ago".
- `GOSSIP_DELAY = 0.1` game-days. `CRIME = {"theft", "vandalism", "hit_npc"}`.
- `tick(...)` runs `1 + (1 if "pip" in CONFIG["npcs"] else 0)` gossip steps. Each step:
  1. Find the oldest eligible memory: `severity >= 10`, `reliability >= 0.25`, `learned_at is None or game_time - learned_at >= GOSSIP_DELAY`, for this player, with at least one NPC that doesn't know its event.
  2. Pick one listener among those who don't know it: `wren` first for crimes, otherwise the first in config order.
  3. Add the memory with `how=f"told_by:{teller}"`, `reliability = teller.reliability / 2`, `severity // 2`, `learned_at=game_time`, and a trust delta of `round(trust_delta(type, "witnessed") * new_reliability)`.

**Tests (replace v1 `test_gossip_spreads_once`):**

### Task 4: Quests (starter, LLM, slay, hand-in, journal)

**Files:** Modify `db.py` (`promises` gains `title, xp, trust, quest_id, target`), `progress.py`, `game.py`, `app.py`, tests.

**Interfaces (`progress.py`):**
- `available_quests(conn, player) -> list`: starter quests not yet accepted, with npc, title, kind, item/mob, count, reward, xp, main.
- `accept_quest(conn, player, quest_id) -> dict`: raises `ValueError` if unknown or already taken. Creates a `promises` row with `kind='quest'`, `deadline=None`.
- `handin(conn, player, npc_id, items: dict[itemstring,int]) -> {"consumed": {itemstring: n}, "completed": [titles], "give": [...], "notices": [...], "xp_gained", "level_up"}`:
  - fills that NPC's open `bring` quests oldest first
  - consumes only what's needed
  - completes the ones that are full: rewards, xp, a `quest_done` trust delta (the quest's trust value), and the notice `Quest complete: <title>`
- `slay` events advance the player's open slay quests whose `target` prefix matches `details.mob`. Completion as above.
- Gifts still advance a matching quest for that NPC (v1 behaviour), now granting quest xp and trust.
- LLM quest offers get `title = f"{count} {item} for {npc name}"`, xp 20, trust 20, no deadline.
- `tick` no longer fails quests (deadline None).
- `journal(conn, player) -> {"active": [...with progress "have/need"], "done": [...]}`.
- Routes:
  - `GET /quests?world&player` returns `{"available", "journal"}`
  - `POST /quest/accept`
  - `POST /quest/handin`

### Task 5: Festival vote

**Files:** Modify `progress.py`, `game.py`, `app.py`. Create `tests/test_festival.py`.

**Interfaces:**
- `festival_status(conn, player) -> {"eligible": bool, "held": bool, "missing_main": [titles], "level": n}`. Eligible means every NPC's main quest is done, level ≥ 4, and the festival hasn't been held.
- `vote(trust) -> "for"|"abstain"|"against"`: ≥30 for, < -10 against, otherwise abstain.
- `ending(votes) -> "hero"|"accepted"|"turned_away"`:
  - hero: for ≥ 2/3 of voters and no against
  - accepted: for > against
  - otherwise turned_away
- `hold_festival(conn, llm, world, player, game_time) -> {"votes": [{"npc_id", "vote", "speech"}], "ending"}`:
  - Raises `ValueError` when not eligible (422).
  - For each NPC, one `npc_dialogue` call with `facts.situation = f"the village festival vote; you vote {vote}; explain why in one or two sentences, citing what you remember"` and `player_message None`.
  - Validated. On failure, a template: `"I vote {vote}."`
  - Records a `festival` event with details `{ending, votes}`, plus a memory for every NPC: "the village voted on the newcomer: <ending>".
  - Sets player flag `festival_held`.
- Routes: `GET /festival?world&player` and `POST /festival {world, player, game_time}`.

### Task 7: Auto-talk, roaming and meetings (Lua)

**Roaming** replaces the v1 wander:
- Daytime (timeofday 0.25-0.75): pick a random place from `npcasso.places` (square, inn door, farm, hall door, market,
  pond, every house door, plus jitter).
- `core.find_path(pos, dest, 40, 1, 3, "A*_noprediction")`, then walk the waypoints at 1.5 n/s.
- Rest 5-15 s on arrival.
- Dusk and night: home, staying within 2 nodes.
- Path fail or 40 s timeout: go home.
- Pause while talking, reacting or gossiping.

**Meetings:** every 1 s, check for another NPC within 3 nodes with no pair cooldown (60 s). Both stop and face each
other. For each online player, `POST /gossip` (lower id tells first, then the reverse). Show line and reply as bubbles.
Resume after 5 s.

Auto-talk as below:

**Files:** Modify `init.lua`

- A globalstep every 0.25 s per player. If the player isn't in a talk or trade window (tracked via `talk[name]`), an NPC is within 2.5 nodes, and the player's look direction is within 45° of the direction to that NPC for 1 s continuously, call `npcasso.open_talk`.
- Per-NPC cooldown: 60 s after the window closes, stored in `autotalk_block[name][npc_id] = os.time() + 60` on close.
- The setting `npcasso.auto_talk` (default true) disables it.
